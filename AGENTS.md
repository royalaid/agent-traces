# AGENTS.md

agent-traces is a native CLI that reads coding-agent session stores. Build, test, and command reference: `README.md`. Store formats: `docs/stores.md`.

## Rollout

A merge whose `Cargo.toml` version has no `vX.Y.Z` tag is released by `.github/workflows/release.yml` and installed on the Mac and the PC by own-tools-sync (`~/git/skills/own-tools-sync`) within about 15 minutes. A merge that keeps the version releases nothing. Run these steps in order after every merge that changes the binary. A step that does not apply to the change is skipped, and the receipt says why. Each step is done when its check passes.

1. **Version and merge.** The PR bumps `version` in `Cargo.toml` (and `Cargo.lock` through `cargo build`) and names it in its title, as in `since: select by last activity (0.2.3)`. `gh pr merge <PR> -R royalaid/agent-traces --squash --delete-branch`. Check: `gh pr view <PR> -R royalaid/agent-traces --json state,mergeCommit --jq '.state, .mergeCommit.oid'` prints `MERGED` and the merge SHA.
2. **Release (automatic).** The push to `main` runs the `Release` workflow: it tests and builds the four targets, checks each binary reports the new version, attests each archive (`actions/attest-build-provenance`), and creates tag `vX.Y.Z` at the merge commit with the four archives and their `.sha256` files. Check: `gh run list -R royalaid/agent-traces -w Release -L 1` shows success for the merge SHA, and `gh release view vX.Y.Z -R royalaid/agent-traces --json assets --jq '.assets[].name'` lists four archives and four `.sha256` files. On a red run, fix forward with a new version. If Actions cannot run at all, build by hand from a detached checkout of the tag with `scripts/package.py` (it lays archives out as the workflow does), `gh release create vX.Y.Z --verify-tag`, and upload; own-tools-sync then refuses the unattested archives, so install those by hand as `README.md`, "Install a release", describes.
3. **Install on the Mac and the PC (automatic).** own-tools-sync runs every 15 minutes on each host. It downloads the host's archive, checks the `.sha256` and `gh attestation verify --source-ref refs/heads/main`, checks the extracted binary's version, and swaps it into the Mac's `~/.local/bin/agent-traces` or the PC's `C:\Users\gwmai\.local\bin\agent-traces.exe`, keeping one `.bak`. Check, on each host: `agent-traces --version` prints `agent-traces X.Y.Z`, `agent-traces where` lists that host's stores, and `python3 ~/git/skills/own-tools-sync/scripts/own_tools_sync.py status` shows `agent-traces` as `updated` or `current`. Ask `codex@skills@desktop-o91444g` over Telepathica for the PC's check.
4. **WSL (manual).** own-tools-sync does not run in WSL. Hand the install to `codex@agent-traces@desktop-o91444g-wsl`: download `agent-traces-x86_64-unknown-linux-musl.tar.gz` and its `.sha256` from the release, verify, and copy the binary to `~/.local/bin/agent-traces`. Check: `agent-traces --version` there prints the new version.
5. **Docs and dependent skills.** The skill lives in the skills repo: `~/git/skills/agent-traces/` (its `references/native-cli.md` names the minimum release that has the features the skill relies on; raise it when the skill starts relying on this one). Update it for new commands, flags, or output, and check the skills that call the CLI: `grep -rl agent-traces ~/git/skills --include='*.md' --exclude-dir=docs`. Then run the skills repo's Rollout section, which carries the change to the apcx-agent-workspace mirror. Telepathica's `telepathica setup` checks for agent-traces on PATH; a renamed command needs a matching change in `~/git/agent-mailbox`. Check: each hit was read and still holds, or its fix rolled out.
6. **chezmoi.** Nothing chezmoi manages names agent-traces today. Check: `grep -n agent-traces ~/AGENTS.md ~/.claude/CLAUDE.md` prints nothing; if it does, follow the Rollout section of `~/.local/share/chezmoi/AGENTS.md`.

Finish with a receipt: each step marked done with its check output, skipped with the reason, or blocked with the failing output.
