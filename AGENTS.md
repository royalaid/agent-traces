# AGENTS.md

agent-traces is a native CLI that reads coding-agent session stores. Build, test, and command reference: `README.md`. Store formats: `docs/stores.md`.

## Where changes land

agent-traces is developed in the Harbor monorepo (`royalaid/harbor`, folder `agent-traces/`, Harbor decisions D042 and D043). `royalaid/agent-traces` is a one-way published mirror of that folder: releases and Actions run there, and nobody commits or opens pull requests there. Run `cargo` from `agent-traces/`, which keeps its own Cargo package; Harbor has no root Cargo workspace. Files under `.github/workflows/` here are inert in Harbor and run in the mirror. Everything in this folder is published to the public mirror, so keep private paths, hosts, identifiers and secrets out of it.

## Rollout

A Harbor merge that changes `agent-traces/` reaches the mirror through `python tools/mirror_component.py sync agent-traces`, which own-tools-sync runs on the PC after it fast-forwards the PC's Harbor checkout (Harbor `docs/runbooks/component-mirrors.md`). A sync whose `Cargo.toml` version has no `vX.Y.Z` tag on the mirror is released by `.github/workflows/release.yml` in the mirror and installed on the Mac and the PC by own-tools-sync (`~/git/skills/own-tools-sync`) within about 30 minutes. A merge that keeps the version releases nothing. Run these steps in order after every merge that changes the binary. A step that does not apply to the change is skipped, and the receipt says why. Each step is done when its check passes.

1. **Version and merge.** The PR bumps `version` in `agent-traces/Cargo.toml` (and `agent-traces/Cargo.lock` through `cargo build`) and names it in its title, as in `agent-traces: since: select by last activity (0.2.3)`. `gh pr merge <PR> -R royalaid/harbor --squash --delete-branch`. Check: `gh pr view <PR> -R royalaid/harbor --json state,mergeCommit --jq '.state, .mergeCommit.oid'` prints `MERGED` and the merge SHA.
2. **Mirror sync (automatic on the PC).** own-tools-sync on the PC moves its clean `main` Harbor checkout to the merge and then runs `python tools/mirror_component.py sync agent-traces`, which pushes one commit `Sync from royalaid/harbor@<short sha>` to the mirror's `main`. Check: `python tools/mirror_component.py status agent-traces` from a clean Harbor `main` shows the merge as the last sync and no pending or foreign commits. If the step did not run or failed, run that sync by hand from a clean, current Harbor `main` checkout; on a refusal, follow "When sync refuses" in the runbook.
3. **Release (automatic).** The sync's push to the mirror's `main` runs the `Release` workflow there: it tests and builds the four targets, checks each binary reports the new version, attests each archive (`actions/attest-build-provenance`), and creates tag `vX.Y.Z` at the sync commit with the four archives and their `.sha256` files. Check: `gh run list -R royalaid/agent-traces -w Release -L 1` shows success for the sync commit, and `gh release view vX.Y.Z -R royalaid/agent-traces --json assets --jq '.assets[].name'` lists four archives and four `.sha256` files. On a red run, fix forward in Harbor with a new version. If Actions cannot run at all, build by hand from a detached checkout of the tag in a clone of the mirror with `scripts/package.py` (it lays archives out as the workflow does), `gh release create vX.Y.Z -R royalaid/agent-traces --verify-tag`, and upload; own-tools-sync then refuses the unattested archives, so install those by hand as `README.md`, "Install a release", describes.
4. **Install on the Mac and the PC (automatic).** own-tools-sync runs every 15 minutes on each host. It downloads the host's archive from the mirror's release, checks the `.sha256` and `gh attestation verify --source-ref refs/heads/main`, checks the extracted binary's version, and swaps it into the Mac's `~/.local/bin/agent-traces` or the PC's `C:\Users\gwmai\.local\bin\agent-traces.exe`, keeping one `.bak`. Check, on each host: `agent-traces --version` prints `agent-traces X.Y.Z`, `agent-traces where` lists that host's stores, and `python3 ~/git/skills/own-tools-sync/scripts/own_tools_sync.py status` shows `agent-traces` as `updated` or `current`. Ask `codex@harbor@desktop-o91444g` over Telepathica for the PC's check.
5. **WSL.** Retired as a client host (2026-10-08): skip, and say so in the receipt. The Linux archive still ships with each release.
6. **Docs and dependent skills.** The skill lives in the skills repo: `~/git/skills/agent-traces/` (its `references/native-cli.md` names the minimum release that has the features the skill relies on; raise it when the skill starts relying on this one). Update it for new commands, flags, or output, and check the skills that call the CLI: `grep -rl agent-traces ~/git/skills --include='*.md' --exclude-dir=docs`. Then run the skills repo's Rollout section, which carries the change to the apcx-agent-workspace mirror. Telepathica's `telepathica setup` checks for agent-traces on PATH; a renamed command needs a matching change in Telepathica. Check: each hit was read and still holds, or its fix rolled out.
7. **chezmoi.** Nothing chezmoi manages names agent-traces today. Check: `grep -n agent-traces ~/AGENTS.md ~/.claude/CLAUDE.md` prints nothing; if it does, follow the Rollout section of `~/.local/share/chezmoi/AGENTS.md`.

Finish with a receipt: each step marked done with its check output, skipped with the reason, or blocked with the failing output.
